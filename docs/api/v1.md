# Tomte API v1

The UI↔server contract. The OSS boundary is undecided, so this API is
designed as a public contract: versioned under `/v1`, no leaked internals.

> **Stability: unstable (alpha).** **Breaking change, 2026-08-31:** the
> reserved break in this notice has been spent (build-conversation spec,
> scoping decision 9). The `steps` document is now the user-facing
> `{id, text}` artifact; the execution form (system prompt, provider,
> model, max_tokens) is server-derived at approval time and no longer
> accepted or returned anywhere under `/v1`. A client that submits the old
> execution-form steps document gets a `400`. Nothing under `/v1` is
> frozen until this notice is removed.

## Authentication

There is no login surface: one install is one user, and the app shell
mints the session at launch (the tenant and owner are created at first
run). "Open in browser" exchanges a single-use, short-TTL handoff token
at `GET /local/handoff?token=` for the session cookie. Browser endpoints
use an opaque
DB-backed session cookie (`__Host-tomte_session`: `Secure`, `HttpOnly`,
`SameSite=Lax`, `Path=/`) resolved on every request to the user, tenant,
and current role; every request is scoped to the session's tenant. There
is no cross-tenant access. Sessions carry a 7-day idle timeout inside a
30-day absolute cap; logout deletes the server-side row.

As defence in depth beyond `SameSite=Lax`, every mutating `/v1` endpoint
applies an Origin policy: absent → allowed (the session cookie is still
required), exactly the configured public origin → allowed, anything else →
`403` before the handler runs.

| Method & path                     | Request body | Response                                                                                                                                                                                        |
| --------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /local/handoff?token=&next=` | —            | `303` to the app (`next` only if a same-origin relative path; default the build conversation) with `Set-Cookie`. The token is single-use and expires in a minute; invalid/used/expired → `403`. |
| `POST /v1/auth/logout`            | —            | `204`, session row deleted, cookie cleared. Idempotent.                                                                                                                                         |
| `GET /v1/me`                      | —            | `200` `{user: {id, email, role}, tenant: {id, name}}` — the UI's bootstrap call.                                                                                                                |

`/internal/*` endpoints are for the run harness only: bearer JWT scoped to
a single run.

## Settings

One configured LLM endpoint per install ("choose where your AI runs").
Switching it is a recorded governance act: the server re-runs the pricing
gate and the permit-provider check for every approved version, recompiles
them against the new endpoint, and records an `endpoint.switched` event —
atomically, or not at all.

| Method & path               | Request body                                                 | Response                                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/settings/endpoint` | —                                                            | `200` `{endpoint: {preset, kind, base_url, connection, run_model, zero_cost, connected}}`; `404` when none is configured yet.                                                                                                                                                                                                                                                                                          |
| `PUT /v1/settings/endpoint` | `{preset, base_url?, connection?, run_model, zero_cost?}`    | `200` on switch. Presets: `anthropic\|openai\|openrouter\|github\|azure\|custom\|local` (azure/custom/local take a base URL; fixed presets ignore one). `409` `{error: "connection_missing"}`, `{error: "unpriced_models", models: […]}` or `{error: "provider_not_permitted", workflows: […]}` — nothing changes on 409. `zero_cost` is accepted for `github` only (free-quota vs paid); `local` is always zero-cost. |
| `GET /v1/settings/prices`   | —                                                            | `200` `{prices: [{base_url, model, input_cents_per_1m, output_cents_per_1m}]}` — user-entered prices, keyed by canonical endpoint base URL.                                                                                                                                                                                                                                                                            |
| `PUT /v1/settings/prices`   | `{base_url, model, input_cents_per_1m, output_cents_per_1m}` | `200`; upsert. `base_url` is explicit so a price can be entered for the endpoint being switched to.                                                                                                                                                                                                                                                                                                                    |
| `GET /v1/settings/budget`   | —                                                            | `200` `{monthly_cap_cents}` (null = the serve-wide default) — the user's local budget: how much Tomte may spend from their key per month.                                                                                                                                                                                                                                                                              |
| `PUT /v1/settings/budget`   | `{monthly_cap_cents}`                                        | `200`; null clears to the default, negative is `400`.                                                                                                                                                                                                                                                                                                                                                                  |

An unpriced model at approval time answers `400`
`{error: "unpriced_model", model, base_url}` — the client renders an
inline two-number price form and retries after `PUT /v1/settings/prices`.
Zero-cost endpoints (`local`; `github` on the free quota) skip the gate
and record zero cost.

## Resources

A **workflow** owns immutable numbered **versions**; each version is the
three artifacts (steps, permit, rubric). At most one version is approved;
only drafts can be approved; a new approval supersedes the old version.
Firing a workflow creates a **run** of its approved version. **Run
events** are the run's audit trail, pushed by the harness.

### `steps` document

The user-facing artifact: what the owner approves, in job language. This
is what the API accepts and returns — schema v1:

```json
{
  "v": 1,
  "steps": [
    { "id": "gather", "text": "Look at last week's support tickets." },
    { "id": "post-digest", "text": "Post a short digest in #team-digest." }
  ]
}
```

- `v` must be `1`; 1–20 steps.
- `id` is a slug (`[a-z0-9]` runs joined by single interior hyphens, ≤ 64
  chars — the rubric criterion-id charset), unique within the document; it
  gives a step stable identity across edits.
- `text` is non-empty, ≤ 500 characters.
- Anything else is rejected with `400` — in particular the pre-decision-9
  execution fields (`system_prompt`, `kickoff`, `provider`, `model`,
  `max_tokens`), which are no longer part of this contract.

Approval compiles the version into a server-derived execution form
(deterministic template assembly against the platform-selected model —
`TOMTE_RUN_PROVIDER`/`TOMTE_RUN_MODEL`; zero model calls) and
stores it alongside the version. The compiled form is served only to the
run harness via `/internal/*` and never appears under `/v1`.

`rubric` is opaque JSON in this API version (any object, including `{}`);
its schema is not yet enforced server-side. `permit` is schema v1 — see
[Permit v1](#permit-v1) below. `schedule` is optional; when present it is
the version's fourth artifact — see [`schedule` document](#schedule-document)
below.

### `schedule` document

```json
{ "cron": "0 9 * * *", "tz": "UTC" }
```

- `cron` is a standard 5-field expression (minute, hour, day-of-month,
  month, day-of-week) — no seconds field, no `@daily`-style descriptors.
- `tz` is required and must be an IANA zone name (`"Local"` is rejected);
  the schedule is evaluated in this zone, so DST transitions follow the
  zone's own rules.
- Unknown fields, a missing `cron`/`tz`, or an unparseable cron expression
  are all rejected with `400` at the point the version is created or
  added, not deferred to run time.

### `workflow`

```json
{ "id": "uuid", "name": "weekly digest", "created_at": "2026-08-30T00:00:00Z" }
```

### `version`

```json
{
  "number": 1,
  "status": "draft",
  "steps": { "...": "the user-facing steps document above" },
  "permit": {},
  "rubric": {},
  "approved_at": null,
  "created_at": "2026-08-30T00:00:00Z"
}
```

### `run`

```json
{
  "id": "uuid",
  "workflow_id": "uuid",
  "version": 1,
  "status": "succeeded",
  "fire_reason": "manual",
  "started_at": "2026-08-30T00:00:00Z",
  "finished_at": "2026-08-30T00:00:01Z",
  "tokens_in": 100,
  "tokens_out": 50,
  "cost_cents": 3,
  "error_kind": null,
  "error_msg": null,
  "output": "This week: 40% of tickets were about the new billing page.",
  "created_at": "2026-08-30T00:00:00Z"
}
```

`fire_reason` is `"manual"` (fired via `POST /v1/workflows/{id}/runs`) or
`"schedule"` (fired by the scheduler). `fire_time` is the scheduled
occurrence's instant for a scheduled run, and is omitted for a manual run.

`started_at`, `finished_at`, `tokens_in`, `tokens_out`, `cost_cents`,
`error_kind`, `error_msg`, and `output` are omitted (not `null`) until the
run reaches that stage.

### `event`

```json
{ "type": "run.start", "payload": {}, "created_at": "2026-08-30T00:00:00Z" }
```

### Permit v1

A permit is the workflow version's approved blast radius. v1 governs LLM
provider egress only:

```json
{
  "v": 1,
  "llm": { "providers": ["anthropic", "openai"], "connection": "default" },
  "connections": {},
  "spend": { "per_run_cents": 50 }
}
```

- `llm.providers` is the allowlist of providers a run may call. An empty
  list (or an omitted `permit`, which defaults to `{"v": 1}`) allows no
  egress — fail-closed, not "unrestricted".
- `llm.connection` names the stored connection (see `/v1/connections`
  above) whose credential the egress proxy injects; it defaults to
  `"default"`. If no connection by that name exists for the tenant and
  the name is `"default"`, the proxy falls back to the operator's
  platform-wide key for that provider, if one is configured.
- `connections` must be empty in v1 (reserved for the future connector
  catalog); a non-empty map is rejected.
- `spend.per_run_cents` is optional; when present it caps that run's
  approved spend and requires a positive integer (zero or negative is
  rejected). The model a run uses is platform policy, priced by
  construction: approval fails `400` if the platform-selected run model
  has no pricing row, and the cap also bounds the compiled `max_tokens`.
- Any other shape — unknown fields, `v` other than `1`, an empty provider
  name — is rejected with `400` at the point the version is created or
  added, not deferred to run time.

Note: `/proxy/*` routes (`/proxy/llm/{provider}/...`,
`/proxy/internal/...`) implement permit enforcement and credential
injection for the run harness. They are bearer-JWT (run token)
authenticated, not session authenticated, and are **not** part of this
public v1 contract — they exist for the harness's own egress, not for UI
or third-party clients.

## Statuses

- **version**: `draft` → `approved` (only one per workflow at a time) →
  `superseded` (once a later version is approved).
- **run**: `pending` → `running` → `succeeded` | `failed`.
